# Management account screens

I19 replaces the management placeholder with account browsing and editing. Start the [demo environment](../development-demo.md), then open `http://localhost:5174` and sign in as administrator or manager. Administrative access is checked by the server before records are requested. Ordinary reception, cafe staff, instructors and customers retain their permitted invitation/self-account controls, but cannot browse or edit other accounts.

The list uses bounded pages of 25 accounts and role/status filters. Next/previous navigate UUID cursors; changing filters returns to the first page. Refresh reloads current records. Pagination is a traversal, not a frozen snapshot. No search or unbounded download is implied. Empty, loading, unavailable and denied states are explicit. The browser keeps account details in component memory only; no profile, credential or action data is stored in browser storage or URLs.

Open **View account** to read email, lifecycle status and confirmation status. Management may edit only name, phone and preferred language through the [profile endpoint](identity-accounts.md). Email and lifecycle status remain read-only; photo and lifecycle workflows are later tasks. Pending/inactive profiles may be corrected without activation. Their role controls are unavailable.

Active accounts permit role assignment through the [role endpoint](identity-roles.md). Existing customer roles remain selected and disabled to preserve customer access/history. The server is authoritative even if a browser has stale roles. Actual changes revoke all target sessions; another open browser loses access on its next request/focus refresh. An actual self role change immediately removes administration and remounts session controls so the operator must sign in again. Identical assignments preserve sessions. Conflicts are shown without raw database information, including last-administration and unintegrated booking/instructor obligations.

Each mutation reads a fresh session CSRF token and sends one POST without automatic retries. Profile and role forms share a pending guard, preventing duplicate or competing saves. Closing, Escape and outside dismissal are blocked until a save settles: cancelling a browser response cannot undo a committed server transaction. Confirmed server values update the row and the reopened editor. Account navigation/unmount cancels obsolete reads and callbacks. A network error may still leave an uncertain server outcome; follow the message to refresh the list before another attempt. Authentication/permission failures clear private management state. No delete, deactivate or reactivate control is presented before lifecycle coordination exists.

Spanish is primary, with equivalent English controls. Labels, dialogs, keyboard navigation, close-focus restoration, loading/status announcements, role legends and pagination controls support accessible operation. Editors scroll within the viewport and layouts fit phones through desktop sizes.
